es5-corpus-asi/ — real, deployed, semicolon-free ES5.1 JavaScript.
Untracked (same convention as es5-corpus/). Files are verbatim upstream release
artifacts; nothing was edited or trimmed. Fetched 2026-07-30.

Purpose: every file here is valid ES5.1 per a real engine (node --check) but
REQUIRES Automatic Semicolon Insertion (ES5.1 §7.9) to parse, so the BASE
ES5.1 CDG grammar (examples/metalang3/resources/es5/grammar.cdg, which
explicitly does not encode ASI) must REJECT all of them.

Verification (see mgroup3/test/kotlin/com/giyeok/jparser/mgroup3/Es5AsiCorpusProbe.kt):
  bibix4 runEs5AsiCorpusProbe
    -> BASE grammar x this dir, expects REJECT for every file; prints the
       first-failure site and classifies it against ES5.1 7.9.1 rule 1.
  bibix4 runEs5AsiCorpusAccept
    -> same corpus against the ASI-encoding grammar, expects ACCEPT.
       Fix ES5_ASI_GRAMMAR in that action to wherever the ASI grammar lands.

Style: literal ';' characters in the whole file (for-headers, strings and regexes
included) -- zepto 21, bean 34, bonzo 27, reqwest 17. Of the statement-ish lines,
zepto 600/600 and bean 295/295 end without a semicolon.

Result on 2026-07-30 (BASE grammar): all four REJECTED. First-failure sites --
  zepto    offset 194  line 4  before '}'  7.9.1 rule 1 clause (b)
  bean     offset 126  line 3  before 'e' of `else`   clause (a)
  bonzo    offset 126  line 3  before 'e' of `else`   clause (a)
  reqwest  offset 262  line 9  before 'e' of `else`   clause (a)
ASI-repair probe (ES5_ASI_REPAIR=1): inserting only semicolons at positions the
parser demands drives the parse forward, and every such position is a legal
7.9.1 site. With the cap at 40 all four files gave 40/40 legal sites and zero
unexplainable ones. With the cap lifted, reqwest was repaired to completion:
220 insertions (123 clause (a), 97 clause (a)+(b)), after which the BASE grammar
ACCEPTS the file -- i.e. ASI is the sole obstacle. That full run takes ~380s for
19KB and was OS-killed on the next file at -Xmx10g, hence the shipped cap.
